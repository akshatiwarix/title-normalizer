## The thesis, in one paragraph

Every GTM stack normalizes job titles with a fuzzy-match lookup table whose error rate is unknown
to the user *and to the vendor*. The received story is that titles are hard because they are messy —
casing, punctuation, `| We're hiring 🚀`. That is the easy part. The hard part is that **the
taxonomy is underdetermined**: there is no fact of the matter about which function `Head of Growth`
belongs to, `Head of Sales` is a Director at 80 headcount and a VP at 2,000, and `Chief of Staff`
has no function at all. Every tool resolves these by silently picking a branch, then propagates the
pick into routing, scoring and the board deck. This repo picks none of them. It returns a
three-state verdict per dimension — `resolved`, `ambiguous` with the full candidate set and the
tokens that forced the fork, or `unknown` with one of five reasons — and it publishes its
**silent-error rate** (resolved *and* wrong) as the headline number rather than an accuracy figure or
a confidence score. It can also tell a *genuine taxonomy fork* (declared multi-value lexicon entry)
apart from a *gap in its own lexicon* (undeclared token conflict), which is the central claim.
Sibling repos own the neighbours: Day 004 `persona-mapper` maps company → committee and *emits*
titles (this is the inverse map), Day 003 `lead-cleaner` owns record hygiene, Day 009 `lead-router`
*consumes* normalized titles, Day 014 `company-classifier` classifies companies. **Do not rebuild
any of them here.** Day 011's only claim is string → structure, with honest abstention.

Five setup facts inherited from Days 001–010:

- Vitest config belongs in `vitest.config.mts` (`.mts`, not `.ts` — the extension is what stops
  Vite's config loader warning about ESM-in-CJS), and it globs `lib/**/*.test.ts` only. Tests
  outside `lib/` will not run.
- `tsc` alone fails on a clean checkout because `LayoutProps` and friends are generated into
  `.next/types`, so `typecheck` must run `next typegen` first. Never "fix" that error by editing
  `app/layout.tsx`.
- `tsconfig.json` sets `noUncheckedIndexedAccess` on top of `strict` — array and record access
  yields `T | undefined`. Handle it; do not reach for `!`.
- Scripts run through `vite-node -c vitest.config.mts` rather than bare `node`, because the engine
  uses extensionless relative imports that Node's ESM resolver rejects and the `@/` alias lives in
  the Vitest config.
- `AGENTS.md` is regenerated by `next dev`. Commit it with your work; deleting it from a diff only
  re-creates the uncommitted change.

## Architecture

```
                    ┌─ server component ──► data/*.ts (Zod-validated at import)
Browser ────────────┤
                    ├─ lib/normalize (pure) ──► same functions client- and server-side
                    │
                    ├─ POST /api/normalize ──► rate limit ──► same pure engine ──► Zod
                    │
                    └─ POST /api/propose  ──► key check ──► rate limit ──► model ──► Zod
                                                              ──► LexiconEntry[] (unapplied)
```

`lib/normalize/` is the engine and is **dependency-free and framework-free** — it imports `zod` and
nothing else. Not `next`, not `react`, not `@/data`, not `@google/genai`, no DOM globals, no
`Date.now`, no `Math.random`. An eslint `no-restricted-imports` rule scoped to that directory
enforces it and the package carries its own `README.md`. This is not stylistic: a normalizer that
cannot reach a network client cannot return an answer that is not a consequence of its arguments and
its lexicon.

| module | responsibility |
|---|---|
| `types.ts` | the type contract — verdicts, roles, entries, reasons, metrics |
| `taxonomy.ts` | 15 functions, 8 rungs, 3 scopes, 4 bands, region tokens; the only place a value is written down |
| `schema.ts` | Zod schemas for corpus, gold, lexicon, API payloads; parsed at import, throws on bad data |
| `tokenize.ts` | string → tokens; junk stripping, script detection, evidence capture |
| `segment.ts` | compound split into role segments; primary selection |
| `lexicon.ts` | the entries; longest-phrase-first matching |
| `resolve.ts` | the pipeline; the fork-versus-gap distinction |
| `ladder.ts` | ordered-scale interval algebra for seniority |
| `persona.ts` | derived (function, band) → persona; ambiguity propagation |
| `evaluate.ts` | the four metrics and confusion matrices, per corpus |
| `export.ts` | CSV serialisation, permalink encode/decode with the cap |
| `index.ts` | the public surface — the boundary test pins it |

`data/` holds the seeded generator, the ~2,000-title generated corpus and the 120-title adversarial
corpus. `lib/propose/` holds the Gemini call, prompt, response schema and rate limiter. `app/` is the
single console: Input · Verdicts · Scorecard · Abstentions.

### The pipeline

```
raw title
 ├─ 1. SCRIPT       non-Latin / non-English signal   ──► unknown (non-english)   (stop)
 ├─ 2. TOKENIZE     strip junk, honorifics, parens, region suffix, normalise case
 │                  nothing role-bearing left        ──► unknown (garbage-only)  (stop)
 ├─ 3. SEGMENT      split on conjunctions → 1..n role segments
 ├─ 4. MATCH        per segment: longest phrase first, then token fallback
 ├─ 5. RESOLVE      per segment per dimension → resolved | ambiguous | unknown
 │                    conflict + no phrase          ──► ambiguous (lexicon-gap)
 │                    conflict + declared fork      ──► ambiguous (taxonomy-fork)
 │                    no hit                        ──► unknown  (no-evidence)
 ├─ 6. PRIMARY      highest ladder rung wins; tie → leftmost segment
 └─ 7. DERIVE       band ← seniority; persona ← (function, band); ambiguity propagates
```

Steps 1–7 are one pure function and no model participates in any of them. The engine ships to the
browser — pasting fifty titles must re-derive every verdict and every metric with no round trip.

**The taxonomy and the lexicon are data, not code.** If you find yourself writing
`if (token === "vp")` inside `resolve.ts`, the fact belongs in `taxonomy.ts` or `lexicon.ts` as an
entry instead.

## Rules that are easy to break by accident

- **Never add a confidence score.** Decision 5. No float, no 0–100, no threshold dial to trade
  coverage against precision. A score is how a guess gets laundered into a number, and a dial is how
  a demo gets tuned to whatever figure flatters it. Ambiguity is expressed as a **candidate set plus
  evidence**, which is auditable and actionable.
- **The headline number is the failure rate.** `silent-error rate` = resolved *and* wrong, over all
  titles. Lead with it in the README and the Scorecard. Accuracy-on-resolved without coverage next
  to it is the vendor lie this repo exists to refuse.
- **The two corpora are never averaged.** Two thousand generated titles would bury the 120 that are
  the actual test. Two columns, always, everywhere — README, Scorecard, sweep output.
- **`taxonomy-fork` and `lexicon-gap` are different facts.** A fork is a declared multi-value entry:
  the ambiguity is in the world, and the output is correct. A gap is an undeclared conflict between
  token entries: the ambiguity is in our file, and somebody has to write a phrase. Collapsing them
  into one "ambiguous" bucket destroys the central claim.
- **Every verdict carries non-empty `because` evidence.** A verdict with no token or phrase behind
  it is a bug, and a test asserts it cannot happen.
- **Exactly one abstention reason per abstention.** Five reasons: `taxonomy-fork`, `lexicon-gap`,
  `no-evidence`, `non-english`, `garbage-only`. Not zero, not two.
- **Ambiguous seniority is a contiguous interval.** The ladder is ordered, so `{Director, VP}` is
  `[Director, VP]`. A non-contiguous candidate set means a lexicon entry is wrong — do not "fix" it
  by widening the representation to an arbitrary set.
- **Never add a 9th rung and never resolve a range by convention.** `Head of Sales` abstains as
  `[Director, VP]`. Inventing a `Head` rung invents a rung no CRM has; picking VP is the silent guess
  this repo indicts.
- **Compound titles are multiple roles, not one ambiguity.** `Founder & CTO` resolves to two roles.
  Flattening it to one, or calling it ambiguous, throws away a fact the string actually carries.
- **Persona is derived and can never be independent.** `persona = Function + Band`. If either input
  is ambiguous the persona is ambiguous over the cross-product; if either is unknown it is unknown.
  The moment persona has its own resolution path, the repo has shipped the contradiction it was
  built to prevent. Hand-named buyer roles (`Economic Buyer`) belong to Day 004.
- **Longest phrase wins, then tokens.** `Sales Engineer` → Sales, never Engineering. `Marketing
  Operations` → RevOps, never Marketing. Every phrase entry carries a `note` saying why it exists, so
  the lexicon doubles as the documentation of every hard case.
- **`ExecGeneral` is phrase-only.** It is reachable through explicit phrases (`CEO`, `Chief of
  Staff`, `Owner`) and never through token fallback, or it becomes the dumping ground that hides the
  abstentions.
- **A meaning-changing string op is not a noise op.** The generator's ten ops are label-preserving by
  construction; anything that could change the answer becomes a hand-curated adversarial case
  instead. This is what keeps noise-invariance from being circular.
- **Lexicon monotonicity is an invariant, not a hope.** Adding an entry may only turn
  `unknown → resolved` or narrow an `ambiguous` set. It may never flip a resolved answer. The sweep
  re-runs the corpus with each entry withheld in turn.
- **No clock, no randomness at runtime.** The generator uses a seeded PRNG and its output is
  committed as JSON, so a stranger reproduces every published number with `npm run sweep` and no
  credentials.
- **No silent truncation, anywhere.** The permalink caps at 100 titles / 4 KB and says so; it does
  not quietly drop the tail. In a tool whose thesis is *no silent behaviour*, that would be the
  funniest possible bug to ship.
- **Nothing a user pastes is persisted.** No database, no logging of input titles.
- **The corpora are authored and synthetic.** No real person is described.

## Gemini conventions (inherited from Days 001–010)

`@google/genai`, model `gemini-3.6-flash`, `responseMimeType: "application/json"` with a native
`responseSchema`, then Zod as the trust boundary — a schema is a request, a validator is a
guarantee. `ThinkingLevel.MINIMAL`: this is constrained generation against a fixed schema, not
reasoning. `temperature: 0`.

Missing key → **501** with a message pointing at the builder. Model failure → **502**. The app must
render both corpora, every verdict, the full Scorecard, the Abstentions grouping, the permalink, the
CSV and `/api/normalize` with `GEMINI_API_KEY` unset. **The model never normalizes a title, never
resolves an ambiguity, never appears in a measured number** — its one job is abstained titles →
proposed `LexiconEntry[]`, landing in the Abstentions pane as a copyable diff that is never written
to disk.
